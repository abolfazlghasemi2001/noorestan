## ۲. اجرا

**الف) تک‌نفره / آفلاین:** فقط `index.html` را در مرورگر باز کن. همهٔ بازی‌ها، جان‌ها، رکوردها، نشان‌ها و چالش روزانه کار می‌کنند. تب دوم همین مرورگر = حالت «محلی» و بازی دونفره.

برای PWA و آفلاین واقعی باید از روی یک سرور باز شود (نه `file://`)، وگرنه سرویس‌ورکر ثبت نمی‌شود:

```bash
bash start.sh              # سپس http://<آی‌پی-دستگاه>:8787
```

**ب) دو نفر روی دو دستگاه (واقعی):**

```bash
bash start.sh              # پورت ۸۷۸۷، رمز مدیر پیش‌فرض
bash start.sh 9000 mypass  # پورت و رمز دلخواه
```

> روی حافظهٔ مشترک اندروید (`/storage/emulated/0`) اجازهٔ اجرا وجود ندارد، پس با `bash start.sh` صدا بزن نه `./start.sh`. مستقیم هم می‌شود: `node server.js`.

سرور آدرسی مثل `http://192.168.1.42:8787` چاپ می‌کند. روی هر دو دستگاه همان آدرس را باز کن، در صفحهٔ «محفل» آدرس `ws://192.168.1.42:8787` را بزن → «اتصال». حالا یک نفر روم بسازد و دیگری با کد ۶ رقمی وارد شود. بازی دوز و اسم فامیل کاملاً دونفره می‌شوند و چت زنده کار می‌کند.

> نکتهٔ اندروید: اگر از کامپیوتر وصل می‌شوی و صفحه باز نمی‌شود، مطمئن شو هر دو دستگاه روی یک Wi-Fi هستند و فایروال پورت را نبسته است.

## ۳. دو مسیر ارتباطی، یک پروتکل

کلاینت یک کد دارد و دو راه رسیدن پیام:

```
        ┌── ws://…  →  server.js            (سرور واقعی، چند دستگاه)
Net ────┤
        └── BroadcastChannel  →  MiniServer  (حالت محلی، چند تب یک مرورگر)
```

قالب پاکت پیام در هر دو یکی است:

```js
{ ns: 'noorestan', from: '<id>', to: '*' | '<peerId>' | 'room:<code>', t: '<نوع>', ... }
```

`ns` مثل امضای برنامه است؛ هر پیامی که این مقدار را نداشته باشد دور انداخته می‌شود.

### پیام‌های پشتیبانی‌شده

| `t` | کار |
|---|---|
| `hello` | معرفی نام/سطح/امتیاز |
| `welcome` | سرور شناسهٔ خودش را می‌دهد (کلاینت آن را می‌پذیرد) |
| `hb` | ضربان (هر ۲۰ ثانیه) |
| `peers` / `rooms` / `lb` | لیست حاضرین، روم‌ها، لیدربورد |
| `rooms:list` | درخواست لیست روم |
| `room:create` / `room:join` / `room:leave` | مدیریت روم |
| `room:spectate` | ورود به‌عنوان تماشاچی (سرور `spectator:true` می‌دهد) |
| `room:joined` / `room:update` / `room:left` / `room:error` | پاسخ‌های سرور |
| `spectate` | «روم پر است، تماشاچی شدی» |
| `room:start` / `room:game` | شروع بازی و حرکت‌ها (سرور-محور) |
| `chat` | پیام روم یا لابی |
| `typing` | «دارد می‌نویسد…» |
| `react` | واکنش زندهٔ ایموجی (فقط از فهرست مجاز سرور) |
| `rtc` | مذاکرهٔ صوتی WebRTC — فقط داخل روم، نقطه‌به‌نقطه؛ صدا هرگز از سرور نمی‌گذرد |
| `friend:req` / `friend:ok` / `friend:no` / `friends` | گراف دوستان |
| `lb:get` / `lb:put` | لیدربورد |
| `admin:broadcast` / `admin:room:close` / `admin:stats` | کارهای مدیر (نیازمند هش رمز) |
| `notif` | اعلان همگانی |

## ۴. قابلیت‌های واقعی (نه شبیه‌سازی)

- **دوز سرور-محور:** سرور نوبت، خانه‌های پر، مرز تخته و پایان بازی را خودش بررسی می‌کند. حرکت خارج از نوبت یا روی خانهٔ پر بی‌صدا رد می‌شود. تقلب از سمت کلاینت ممکن نیست.
- **ربات شکست‌ناپذیر:** مینی‌مکس کامل با هرس آلفا-بتا؛ کل درخت بازی پیمایش شده و هیچ مسیری به بردِ انسان نمی‌رسد (تست می‌کند).
- **اسم فامیل آنلاین:** دورها، حرف هر دور، انتظار برای همه، نتایج و شروع دور بعد (فقط میزبان) روی سرور.
- **SHA-256 دست‌ساز:** چون `crypto.subtle` روی `http://` (شبکهٔ محلی) وجود ندارد، هش رمز مدیر با پیاده‌سازی خالص JS انجام می‌شود. با ۱۱ بردار تست تأیید شده.
- **جان‌ها:** ۵ جان، هر ۳ دقیقه یک جان برمی‌گردد (بر پایهٔ زمان واقعی، نه تایمر).
- **ترکیب (Combo)، رکورد شخصی هر بازی، ۲۴ نشان، سطح و XP.**
- **چالش روزانه:** با RNG بذردار، برای یک روز یکسان در همهٔ دستگاه‌ها؛ زنجیرهٔ روزها (streak) و جایزهٔ فزاینده.
- **۴ پوسته:** شب، اقیانوس، جنگل، سلطنتی.

## ۶. تست‌ها

```bash
node _harness.js      # ۵۸۸ سنجش منطق کلاینت (هش، جان، دوز، اسم فامیل، روم، قرآن، تلاوت، تصویرسازی، معارف، سکه، فروشگاه، نصب، آفلاین و صوت)
node _servertest.js   # ۶۶ سنجش سرور واقعی روی سوکت واقعی
```

هر دو باید با «۰ ناموفق» تمام شوند. تست سرور روی پورت ۸۷۹۹ یک نمونهٔ مستقل بالا می‌آورد و بعد پاک می‌کند.

سه نکتهٔ فنی دربارهٔ همین تست‌ها، چون هر سه یک‌بار ما را فریب داده‌اند:

- **هارنس `requestAnimationFrame` را ناهمگام می‌کند.** مرورگر rAF را در نوبت بعدی صدا می‌زند؛ اگر استاب همگام باشد، هر حلقهٔ انیمیشنی به «سرریز پشته» می‌کشد و خطایی می‌سازد که در مرورگر هرگز رخ نمی‌دهد.
- **خطاهای دیرهنگام گرفته می‌شوند.** تایمری که پس از پاک شدن وضعیتِ بازی تیک می‌زند، در مرورگر خطای رسیدگی‌نشده می‌دهد و کاربر فقط می‌بیند برنامه از کار افتاد. `uncaughtException` و `unhandledRejection` ثبت می‌شوند و در پایان به‌شکل سنجش گزارش می‌شوند — پس تست‌ها پیش از خروج ۱.۶ ثانیه زنده می‌مانند تا تایمرهای جامانده فرصت تیک زدن داشته باشند.
- **سرورهای سرگردان کشته می‌شوند.** اگر اجرای پیشین نیمه‌کاره بمیرد، سرور تست روی پورت ۸۷۹۹ زنده می‌ماند و اجرای بعدی بی‌خبر به سرورِ کهنه وصل می‌شود؛ یعنی نتیجهٔ تست‌ها دروغ می‌شود. `_servertest.js` اول هر پردازنده‌ای را که با همین پورت و همین فایل داده بالا آمده می‌کشد و بعد تا آماده شدن واقعی سرور (`/health`) صبر می‌کند، نه یک خواب ثابت.

**`selfTest()` درون برنامه:** هر ۹۰ سنجش، داخل خود برنامه هم هست. در کنسول مرورگر `selfTest()` را صدا بزن، یا نشانی را با `?debug=1` باز کن تا پنل اشکال‌زدایی هم بیاید.

## ۶.۵ تازه‌های نسخهٔ ۱۴.۲ — تصویر، تلاوت و صدا

### الف) پردهٔ آغازین قرآنی
پیش از هر چیز، پرده‌ای تمام‌صفحه با **نگارهٔ قرآن گشوده** (گنبد، گلدسته، هالهٔ نور و ستارهٔ هشت‌پر)،
نام **نورستان** با درخشش طلایی، «﷽»، نوار پیشرفت درصدی و پیام‌های گردان (آیه، حدیث، نکته) نشان داده
می‌شود و بعد کنار می‌رود.

- همهٔ نگاره‌ها **SVG درون‌خطی** هستند — هیچ فایل تصویری بیرونی لازم نیست، پس روی گوشی آفلاین هم دیده می‌شوند.
- دو محافظ دارد: اگر کاربر «ورود به نورستان» را بزند فوراً کنار می‌رود؛ اگر JavaScript به هر دلیلی
  از کار بیفتد، یک انیمیشن CSS پرده را در ثانیهٔ ۱۱ خودش کنار می‌برد. `window.onerror` هم لایهٔ سوم است.

### ب) بخش «تلاوت قرآن» 🎧
تب تازهٔ `#quran` (و کارت «تلاوت قرآن» در دستهٔ آموزش قرآن، و دکمهٔ 🎧 در نوار بالا):

- **۱۰ قاری نامدار جهان**: العفاسی، عبدالباسط، منشاوی، حصری، السدیس، المعیقلی، الغامدی، الشاطری، العجمی، أیوب.
- **آیه‌به‌آیه**: جدول همهٔ آیه‌های سوره، پخش، آیهٔ بعد/قبل، «تا آخر سوره» (صف خودکار)، تکرار آیه (۳/۵ بار) و سرعت (۰٫۷۵× تا ۱٫۵×).
- **دو منبع با واپس‌روی خودکار**:

  | منبع | نشانی | ویژگی |
  |---|---|---|
  | EveryAyah | `everyayah.com/data/<قاری>/<سوره۳رقم><آیه۳رقم>.mp3` | آیه‌به‌آیه، ده‌ها قاری |
  | Islamic Network | `cdn.islamic.network/quran/audio/128/<نسخه>/<شمارهٔ سراسری آیه>.mp3` | پایدارتر، ولی فقط چند قاری |

  اگر منبع اول جواب ندهد (یا برای آن قاری وجود نداشته باشد) دومی خودکار امتحان می‌شود؛ اگر هر دو
  شکست بخورند پیام روشن فارسی نشان داده می‌شود. منبع پیش‌فرض از تنظیمات قابل تغییر است.
- **متن عثمانی + ترجمهٔ فارسی** هر آیه از AlQuran Cloud گرفته و در `localStorage` ذخیره می‌شود؛
  بار دوم بدون اینترنت هم خوانده می‌شود. (۱٫۱MB برای کل قرآن — به‌ازای هر سوره ذخیره می‌شود، نه یک‌جا.)
- **نوار پخش کوچک** بالای نوار پایین: هنگام گشتن در صفحه‌های دیگر هم پخش ادامه دارد.
- در بازی «سفر سوره‌ها» دکمهٔ **🎧 شنیدن این آیه** اضافه شد؛ هر سورهٔ بازی حالا شمارهٔ سوره و شمارهٔ آیه
  را می‌داند و همان آیه را از قاری انتخابی می‌خواند.

> چرا دو منبع؟ چون نشانی‌های CDN بیرونی‌اند و ممکن است روزی عوض شوند. `QSOURCES` تنها جای نگهداری
> نشانی‌هاست؛ برای افزودن منبع تازه فقط یک عضو به همان آرایه اضافه کن. آزمون‌ها نشانی‌ها را با
> نمونهٔ مرجع (آیةالکرسی = شمارهٔ سراسری ۲۶۲) می‌سنجند.

### ج) موتور صدای سه‌بعدی
`Sound` بازنویسی شد و همان نام‌های پیشین را نگه داشت، پس هیچ‌جای برنامه نشکست:

- `AudioContext` با گرهٔ مادر + **Convolver (طنین سالن)** — پاسخ ضربه در زمان اجرا ساخته می‌شود.
- پوش **ADSR** روی هر نُت (پیش‌تر شروعِ ناگهانی بود و «تق» می‌داد) و نُت‌های دولایه برای گرمی صدا.
- متدهای تازه: `click`، `chime`، `fanfare`، `whoosh`، `page`، `noise` (نوفهٔ باندگذر با جاروب بسامد).
- احترام کامل به کلید «🔇 صدا خاموش» — با خاموش بودن صدا هیچ نُتی ساخته نمی‌شود.

### د) نگارخانهٔ تصویری `Art`
`Art.mushaf()` (قرآن گشوده)، `Art.panorama()` (مسجد شبانه با ماه)، `Art.patternTile()` (کاشی بی‌درز
هشت‌پر)، `Art.band()` و `Art.rays()`. همه رشتهٔ SVG برمی‌گردانند؛ `Art.asBg` آن را به `data URI`
تبدیل می‌کند تا پس‌زمینهٔ CSS شود (نمای مسجد در سربرگ خانه، کاشی محو پشت کل برنامه، مدال هر قاری).

### ه) دادهٔ قرآن درون برنامه
`QURAN` هر ۱۱۴ سوره را با نام، شماره و شمارش آیه در خود دارد و `offset` هر سوره (شمارهٔ سراسری آیه)
را می‌سازد. آزمون‌ها جمع را با عدد مرجع **۶۲۳۶** و آیةالکرسی را با **۲۶۲** می‌سنجند.

|---|---|---|
| **نمایشی** (`--f-disp`) | گلزار نستعلیق، نستعلیق نو (Noto)، وزیرمتن | نام **نورستان**، تیترها، سربرگ دسته‌ها |
| **قرآن** (`--f-quran`) | امیری، شهرزاد نو، وزیرمتن | متن عثمانی در همهٔ صفحه‌ها |

- فونت پیش‌فرض نمایشی **گلزار نستعلیق** است؛ در «حساب من ← تنظیمات» دکمهٔ 🌿 **نستعلیق**
  یک‌ضربه‌ای بین نستعلیق و وزیرمتن جابه‌جا می‌کند و 🖋 هر دو نقش را با **نمونهٔ زندهٔ خط** نشان می‌دهد.
- **تنبلی (lazy):** هیچ فونتی در بار نخست دانلود نمی‌شود؛ فقط فونتی که واقعاً انتخاب شده با
  تزریق یک `<link>` از jsDelivr می‌آید. اگر نیامد، فونت پیشین می‌ماند و برنامه نمی‌شکند.
- نستعلیق **وزن ۴۰۰** می‌گیرد (وزن درشت، حرف‌ها را کج و خراب می‌کند) و ارتفاع خطش
  ۲٫۱۵ تا ۲٫۲۵ است تا اعراب و کشیده‌ها بریده نشوند.

```
--f-disp / --f-disp-w / --f-disp-lh   →  نقش نمایشی
--f-quran / --f-quran-w / --f-quran-lh →  نقش متن قرآن
--read-size                            →  اندازهٔ متن در مصحف‌نما
```

### ب) مصحف‌نما 📖 — صفحهٔ `read`
صفحهٔ تازه‌ای برای **خواندن** (نه فقط شنیدن):

- هر آیه یک ردیف: **شمارهٔ فارسی** در مدال گرد، متن عثمانی راست‌چین، و زیرش ترجمهٔ فارسی.
- **روی هر آیه بزن** تا همان آیه خوانده شود؛ آیهٔ در حال پخش با نوار طلایی کنار و رنگ روشن
  مشخص می‌شود و با هر آیهٔ بعد خودکار جلو می‌رود.
- «﷽» بالای سوره‌ها (جز فاتحه و توبه). **بِسْمِلّه از آیهٔ اول جدا می‌شود** — چون AlQuran Cloud
  آن را به آیهٔ اولِ بیشتر سوره‌ها چسبانده می‌دهد و اگر جدا نشود، آیهٔ اول غلط شمرده می‌شود.
- ابزارها: سورهٔ قبل/بعد، گزینش سوره با جستجو، **ا−/ا+** اندازهٔ متن (۱۶ تا ۵۴ پیکسل، در
  `Store` می‌ماند)، روشن/خاموش کردن ترجمه، «پخش سوره»، تغییر فونت قرآن، و 🔖 **نشانهٔ من**
  (آخرین جای خوانده‌شده با تاریخ).
- راه‌های رسیدن: دکمهٔ 📖 در سربرگ «تلاوت»، دکمهٔ «خواندن این سوره در مصحف‌نما» پایین همان صفحه،
  **آیهٔ روز** در خانه، و دکمهٔ «خواندن سوره در مصحف‌نما» در بازی «سفر سوره‌ها».

### ج) آیهٔ روز 🌙
کارت طلایی بالای خانه، **بی‌نیاز به اینترنت**: ۱۲ آیهٔ برگزیده با متن دقیق عثمانی و ترجمهٔ
انصاریان از پیش در خود فایل ذخیره شده‌اند. انتخاب آیه با **تاریخ روز** (هستهٔ قطعی، نه تصادفی)
تعیین می‌شود، پس در همهٔ دستگاه‌ها یک روز، یک آیه است. دکمه‌های ▶️ شنیدن، 📖 خواندن سوره و 📋 رونوشت.

### د) ترجمه‌های فارسی
شش ترجمهٔ بررسی‌شده: **انصاریان، فولادوند، مکارم شیرازی، الهی قمشه‌ای، خرمشاهی، آیتی**.
با تغییر ترجمه، متن هر سوره یک بار دیگر گرفته و **زیر کلید جداگانه** ذخیره می‌شود
(`noorestan_qtext_<ترجمه>_<سوره>`)، پس می‌توانی بین ترجمه‌ها جابه‌جا شوی بی‌آنکه کش قبلی خراب شود.

> در «تنظیمات» دکمهٔ **🧹 پاک کردن متن ذخیره‌شده** تعداد سوره‌های کش‌شده را نشان می‌دهد و با
> یک تأیید آزاد می‌کند. متن‌های بلندتر از ۹۰۰KB وارد حافظهٔ دستگاه نمی‌شوند (فقط در رم می‌مانند)
> تا `localStorage` پر نشود.

## ۶.۷ تازه‌های نسخهٔ ۱۴.۴ — آزمون معارف و پرسش‌های شیعی

### الف) سیزده فونت فارسی در دو نقش
فهرست فونت‌ها گسترده شد و در گزینشگر **گروه‌بندی** شد (نستعلیق، نمایشی، خوانا / نسخ قرآن، …).
هر ردیف **نمونهٔ زندهٔ خط** خودش را نشان می‌دهد و تیک انتخاب دارد.

| نقش | گزینه‌ها |
|---|---|
| **نمایشی** (۸ فونت) | گلزار نستعلیق، نستعلیق نو، لاله‌زار، مرکزی، صمیم، شبنم، ساحل، وزیرمتن |
| **قرآن** (۵ فونت) | امیری، نسخ نو (Noto)، شهرزاد نو، لطیف، وزیرمتن |

- نام **نورستان** و تیترها **گرادیان طلایی** گرفتند (متن با `background-clip:text` برش می‌خورد و
  سایهٔ طلایی زیرش می‌نشیند) — روی نستعلیق درشت‌تر و با ارتفاع خط بازتر، تا کشیده‌ها و اعراب بریده نشوند.
- یک ویژگی تازهٔ ریشه‌ای: `<html>` سه نشانهٔ `data-disp` / `data-quran` / `data-nast` می‌گیرد،
  پس CSS می‌تواند **مخصوص نستعلیق** اندازه و ارتفاع خط را جدا تنظیم کند، بی‌آنکه به بقیهٔ فونت‌ها دست بزند.

### ب) آزمون معارف 🏅 — خودت بچین
کارت تازهٔ «آزمون معارف» در دستهٔ آموزش قرآن. با زدنش یک پنجره باز می‌شود:

- **سطح دشواری**: 🎲 همه / 🌱 آسان / 🌿 متوسط / 🔥 دشوار.
- **موضوع‌ها**: یازده موضوع، با شمار پرسش هر کدام؛ می‌توانی هر تعداد را روشن و خاموش کنی
  (دکمه‌های «✅ همه» و «✖️ هیچ‌کدام» هم هست).
- زیر پنجره می‌نویسد چند پرسش با این ترکیب در دسترس است و چند پرسش پرسیده می‌شود؛
  اگر ترکیب خالی باشد، دکمهٔ شروع خودش خاموش می‌شود.
- رکورد آزمون زیر کلید `exam_best` ذخیره می‌شود.

موضوع‌ها از یک **دفتر** می‌آیند (`DATA.TOPICS_DEF` + `TOPICS`). هر موضوع یک `bank` دارد؛
برای افزودن موضوع تازه فقط یک ردیف در دفتر و یک بانک در `DATA` لازم است — گزینشگر خودش
ردیف، شمارش و صافی سطح را می‌سازد.

| موضوع | بانک | شمار |
|---|---|---|
| 📖 دانش قرآنی | `DATA.quiz` | ۳۱ |
| 🔤 معنی و واژه | `DATA.meaning` | ۲۴ |
| 🕌 چهارده معصوم | `DATA.ahlulbayt` | ۲۶ |
| 🕯️ عاشورا و کربلا | `DATA.karbala` | ۱۶ |
| 🤲 غدیر و ولایت | `DATA.ghadir` | ۱۱ |
| 📜 احکام جعفری | `DATA.ahkam` | ۲۰ |
| 📿 ادعیه و زیارات | `DATA.dua` | ۱۶ |
| 🌙 مهدویت و غیبت | `DATA.mahdavi` | ۱۳ |
| ⚖️ اصول و فروع دین | `DATA.usul` | ۸ |
| 📜 نهج‌البلاغه | `DATA.nahjPick` | ۲۵ |
| 🇮🇷 ایران‌شناسی | `DATA.iran` | ۲۴ |

پس هیچ محتوایی دوباره‌نویسی نشده است.

### ج) پرسش‌ها دیگر ابتدایی نیستند
- **هر پرسش سه چیز تازه گرفت**: `d` (سطح ۱ تا ۳)، `why` (توضیح کوتاه پس از پاسخ) و `src` (منبع).
  کتابخانهٔ پرسش از **۷۶** به **۲۳۸** رسید (۲۱۳ پرسش چهارگزینه‌ای + ۲۵ پرسش معنی حکمت).
- پس از پاسخ، جعبهٔ توضیح باز می‌شود: «✅ درست بود» یا «❌ پاسخ درست: …»، بعد **چرا** و
  سپس **📚 منبع**. در حالت عادی ۳٫۴ ثانیه می‌ماند و دکمهٔ «سوال بعدی ⏭» هم دارد؛
  در «سرعت نور» همان ۹۰۰ms پیشین می‌ماند تا ریتم تند نشکند.
- بالای هر پرسش، منبع و برچسب سطح (آیه/سوره + 🌱/🌿/🔥) نشان داده می‌شود.

**پرسش‌های نادرست پیشین که اصلاح شدند:**

1. «کدام سوره به نام حشره است؟» — هم النحل (زنبور) و هم النمل (مورچه) حشره‌اند → به «سورهٔ نحل به نام کدام جانور است؟» تغییر کرد.
2. «کدام سوره به نام پرنده است؟» با پاسخ «النحل» — زنبور پرنده نیست → پرسش با پاسخ درست «هدهد» بازنویسی شد.
3. «سجدهٔ واجب…» با پاسخ «السجدات» — چنین سوره‌ای وجود ندارد → پاسخ به چهار سورهٔ عزائم تغییر کرد.
4. «ترتیب سوره‌ها بر اساس طول سوره‌ها» — با عقیدهٔ **توقیفی** بودن ترتیب ناسازگار بود → اصلاح شد.
5. «قدیمی‌ترین دانشگاه جهان… جندی‌شاپور» — ادعای نادرست → به «در زمان کدام سلسله بنیان نهاده شد؟» تغییر کرد.
6. «ساز قانون → پرویز مشکاتیان» — او سنتور می‌نواخت → پرسش به «کیهان کلهر → کمانچه» تغییر کرد.
7. «بلندترین آبشار ایران» و «واحد پول ایران → ریال» — هر دو محل اختلاف → برداشته شدند.
8. در یک پرسش، گزینهٔ «النمل» دو بار تکرار شده بود → رفع شد.

### د) منابع پرسش‌ها
هر پرسش `src` دارد و منابع **گوناگون**اند، نه یک کتاب. از این‌ها میان منابع دیده می‌شود:
`قرآن` (با شمارهٔ سوره و آیه)، `شیخ مفید، الارشاد`، `شیخ صدوق، کمال‌الدین`،
`شیخ کلینی، الکافی`، `شیخ صدوق، عیون اخبار الرضا`، `تاریخ طبری`، `ابن‌قولویه، کامل‌الزیارات`،
`شیخ طوسی، مصباح المتهجد`، `سید بن طاووس، اقبال الاعمال`، `صحیفهٔ سجادیه`، `توضیح‌المسائل مراجع`،
`ویکی‌شیعه`، `علامه امینی، الغدیر` و منابع تاریخ و جغرافیای ایران.

> **روش کار:** پرسش‌ها را از منابع اینترنتی (بیشتر ویکی‌شیعه) با `curl` بیرون کشیدم و
> یک‌به‌یک سنجیدم. جاهایی که منابع اختلاف داشتند، پرسش **برداشته شد** — نه اینکه یک روایت
> دلخواه انتخاب شود. نمونه‌ها: تاریخ دقیق مباهله، نام مادر امام سجاد، نام مادر امام عسکری،
> جای دفن سر امام حسین، قاتل امام حسین، و طول امامت بیشتر امامان.
> جاهایی هم که فقط «مشهور» بود و نه متفق، با قید نوشته شد: «حدود ۷۲ نفر» برای شهیدان کربلا،
> و شب چهارشنبه برای دعای توسل با برچسب «رسم رایج در ایران».

### ه) گنجینهٔ نهج‌البلاغه 📜
کارت تازهٔ «نهج‌البلاغه» در دستهٔ آموزش قرآن. با زدنش فهرست **۲۵ سخن سنجیده** از امام علی (ع) باز می‌شود:

- هر کارت: شمارهٔ فارسی در مدال طلایی، **متن عربی مُعرَب** با فونت قرآن، ترجمهٔ فارسی، و 📚 شمارهٔ منبع.
- فهرست بلند است و در خودش می‌لغزد (`max-height: 56vh`)، پس پنجره از صفحه بیرون نمی‌زند.
- پایینش دکمهٔ **🏅 آزمون معنی حکمت‌ها**: متن عربی نشان داده می‌شود و باید ترجمهٔ درست را از میان
  چهار ترجمه یافت. رکوردش در `nahj_best` می‌ماند.
- بانک `DATA.nahj` و پرسش‌هایش `DATA.nahjPick` (۲۵ پرسش). گزینه‌های نادرست، ترجمهٔ **سخنان دیگر همان
  بانک**اند و **نزدیک‌ترین طول** انتخاب می‌شود تا از روی بلندی گزینه‌ها نشود پاسخ را حدس زد.
- نهج‌البلاغه در گزینشگر «آزمون معارف» هم یک موضوع مستقل است.

> **دقت تاریخی:** هر ۲۵ شماره در **دو منبع مستقل** دیده شد (متن مُعرَب `alseraj.net` با تصحیح
> صبحی صالح، و فهرست کلمات قصار در ویکی‌شیعه با ترجمهٔ شهیدی) و یکی بود. آنچه در نهج‌البلاغه پیدا نشد
> یا شماره‌اش تأیید نشد **کنار گذاشته شد** — از جمله «العلم نور»، «الناس نيام فإذا ماتوا انتبهوا»،
> «الحسد آفة» و «الجاهل من عرف نفسه». دو مورد هم که حکمت مستقل نیستند صریحاً برچسب خوردند:
> «لا تكن عبد غيرك» در **نامهٔ ۳۱** است و «من كثر كلامه كثر خطؤه» فرازی از **حکمت ۳۴۹**.
> ترجمهٔ دو فراز خطبه (طاووس ۱۶۵ و خفّاش ۱۵۵) چون ترجمهٔ قابل‌استنادی یافت نشد، بیرون ماند.

### و) سه نشان تازه 🎖️
`exams` (سه آزمون معارف)، `ahlulbayt` (بیست پاسخ درست از معارف اهل بیت) و `ahkamexpert`

## ۶.۸ تازه‌های نسخهٔ ۱۵ — پاک‌سازی، پویانمایی، معارف و چندنفرهٔ ۸ نفره

### الف) ساختار تمیزتر در همان تک‌فایل
هنوز یک فایل است و هنوز صفر وابستگی — ولی درونش منظم شده:

- **CSS در `@layer`:** `tokens, base, layout, comp, anim, theme, motion, utils`. ترتیب لایه‌ها از ویژگی (specificity) قوی‌تر است، پس دیگر برای رد کردن یک قاعده لازم نیست `!important` بگذاری.
- **همه‌چیز از متغیرهای CSS می‌آید** (`--bg`, `--card`, `--acc`, `--mut`, …) و پوسته‌ها فقط همان متغیرها را عوض می‌کنند.
- **چیدمان با Grid و Flexbox و `container queries`.**
- **JS در ماژول‌های نام‌دار با JSDoc:** `U`, `Store`, `Router`, `Net`, `FX`, `Theme`, `Sound`, `Haptic`, `Assets`, `QuranUI`, `ReaderUI`, `Games`, `Launcher`, `A11y`, `Debug`, `Missions`, `Week`, `Progress`, `Adaptive`, `Beat` و موتورهای بازی.
- **ES2022+:** `?.`, `??`, `Object.entries`, `Array.prototype.at`, پخش (spread).

### ب) پویانمایی — همه روی `transform` و `opacity`
| جای | چه می‌شود |
|---|---|
| پردهٔ آغازین | پارالاکس با حرکت ماوس و ژیروسکوپ، آشکارسازی بسم‌الله با ماسک، ذرات Canvas، خروج با پردهٔ آیریس |
| خانه | کارت‌ها با فاصلهٔ ۵۰ms یکی‌یکی می‌آیند، تیلت سه‌بعدی، Ken Burns روی تصویر، شمارش عددی، درخشش نوار پیشرفت |
| درون بازی | پرسش با لغزش و محو، گزینه‌ها پله‌پله؛ پاسخ درست = تپش سبز + ذرات ستاره + لرزش نرم؛ غلط = لرزش افقی + قرمز پریده + لرزش گوشی؛ کمبو = پاپ + ذرات آتش |

| محفل | لغزش پیام، سه‌نقطهٔ «می‌نویسد»، حلقهٔ تپش دور آواتار، نمودار زندهٔ ستونی |
| سراسری | گذار بین صفحه‌ها، جهش آیکن نوار پایین، ورود فنری توست و خروج با محو+لغزش، مقیاس+محو برای پنجره‌ها |

همه‌اش با `prefers-reduced-motion` و `html[data-motion="off"]` خاموش می‌شود.

### ج) قابلیت‌های تازه
- **حالت تمرکز قرآن** — همه‌چیز جز متن کنار می‌رود (`quran.focus`).
- **گزینشگر قاری** با آواتار رنگی و **پیش‌نمایش ۵ ثانیه‌ای**؛ ۱۰ قاری نامدار.

- **تکرار شبانه** با کم شدن تدریجی صدا.
- **سه بازی معارف تازه:** «حدیث‌یاب» (۶۲ حدیث)، «چهارده معصوم» (۱۴ معصوم)، «نجوا» (۱۴ دعا).
- **دشواری سازگار** (`Adaptive`) و **«رکوردت را بزن»** (`Beat`).
- **روم تا ۸ بازیکن + تماشاچی**، واکنش زندهٔ ایموجی، «می‌نویسد…»، **صدای اختیاری WebRTC**، **دوستان** و **پیوند دعوت**.
- **مأموریت‌های روزانه (۳ از ۱۰)**، صفحهٔ **کلکسیون نشان‌ها** (۲۴ نشان)، **درخت دانش**، و **جایزهٔ هفتگی لیدربورد**.
- **دسترس‌پذیری:** برچسب `aria` روی دکمه‌های بی‌نام، ناوبری با کلید، اعلام تغییر صفحه، پوستهٔ روشن، و تلاش دوبارهٔ هوشمند در شبکه (پنج بار با عقب‌نشینی نمایی تا ۱۵ ثانیه).
- **ذخیرهٔ خودکار وضعیت بازی:** اگر وسط بازی صفحه را ببندی، دفعهٔ بعد بالای صفحهٔ بازی‌ها نوار «ادامه بده» می‌آید. فهرست پرسش‌ها هم ذخیره می‌شود، پس سرِ همان سوال ادامه می‌دهی نه یک بازی بر زدهٔ تازه.

  کدام بازی‌ها: **آزمون‌های پرسشی** (سوالات قرآنی، معنی کلمه، اطلاعات ایران، سرعت نور)، **حافظه**، و **دوز آفلاین**.

  کدام بازی‌ها نه، و چرا:
  - **آزمون معارف و نهج‌البلاغه** — پایانشان به یک callback محلی گره خورده که در JSON جا نمی‌گیرد. بازی بازگردانده‌شده بی‌سروصدا رکورد ثبت نمی‌کرد، و رکورد گم‌شده از نبودِ «ادامه بده» بدتر است.
  - **دوز آنلاین** — وضعیت آن‌جا تنها مرجعش سرور است، نه حافظهٔ این دستگاه. ادامه دادن از تختهٔ محلی یعنی تقلب.
  - **سفر سوره‌ها، پازل حروف، تطبیق** — فعلاً ذخیره نمی‌شوند.

  هر بازی کهنه‌تر از یک شبانه‌روز نادیده گرفته می‌شود، و snapshot بی‌شکل (بازمانده از نسخهٔ قدیمی) پاک می‌شود تا «ادامه بده» هرگز گیر نکند.
- **`selfTest()`** در کنسول (۷۱ سنجش) و **پنل `?debug=1`** — هر دو یک پیاده‌سازی مشترک دارند.

### د) چند چیز که خراب بود و درست شد
1. **دکمهٔ 🎮 برنامه را می‌خواباند.** `Launcher.open()` هم `Router.go('play')` می‌کرد و هم صفحه را می‌کشت؛ قلابِ صفحهٔ «بازی» وقتی `#pgBody` خالی بود همان `open()` را صدا می‌زد، پس قلاب → `open` → `Router.go` → قلاب … تا **سرریز پشته** بی‌پایان می‌چرخید. `open()` به `open()` + `paint()` شکسته شد و قلاب حالا `paint()` صدا می‌زند. یک نگهبان بازگشت هم در تست هست.
2. **`Net.send` وجود نداشت.** پنج جا (واکنش، «می‌نویسد»، و چهار فراخوان مذاکرهٔ صوتی) به تابعی تکیه می‌کردند که هرگز نوشته نشده بود؛ خطا در `try/catch` بلعیده می‌شد و این قابلیت‌ها بی‌صدا از دست می‌رفتند.
3. **`selfTest` بانک اشتباه را می‌سنجید.** کلیدهای کوتاه به رشتهٔ مسیر (`'DATA.quiz'`) نگاشت شده بودند ولی حلقه‌ها `DATA[k]` می‌خواندند؛ یعنی به‌جای بانک پرسش، «جاهای خالی سوره» و متن خام نهج‌البلاغه سنجیده می‌شد و ۴۹ پرسش سالم، خراب گزارش می‌شد.
4. **انحراف (offset) سوره‌ها صفرپایه است** — سنجش، سورهٔ ۱۱۴ را یکی اشتباه می‌گرفت.
5. **تایمری که پس از پاک شدن وضعیت تیک می‌زد** برنامه را با استثنای رسیدگی‌نشده می‌خواباند؛ حالا نگهبان دارد و تست هم آن را می‌گیرد.
6. **سرور تستِ سرگردان** باعث می‌شد اجرای بعدی به سرور کهنه وصل شود و نتیجهٔ تست‌ها دروغ شود.

## ۶.۹ تازه‌های نسخهٔ ۱۶ — سکه، فروشگاه، زنجیره، پروفایل و راهنمای آغاز

### الف) پروفایل کامل 🙋
تب تازهٔ **پروفایل** (اکنون تب نخستِ «حساب من») یک صفحهٔ کامل است: چهرک بزرگ
با حلقهٔ نبض، نوار تجربه تا سطح بعد، سکه، شمار نشان‌ها، ویرایش نام و شعار، و
شناسنامه‌ای با تاریخ عضویت، تعداد بازی‌ها، پرکارترین بازی و حساب سکه‌ها.

**چهرک رنگ پایدار دارد:** رنگ از هشِ FNV-1a شناسهٔ بازیکن حساب می‌شود، نه از
یک عدد ذخیره‌شده. پس اگر حافظه پاک شود و شناسه بماند، چهرک همان رنگ همیشگی
را دارد. کاربر می‌تواند دستی هم رنگ و ایموجی بردارد؛ انتخاب او بر هش مقدم است.

### ب) سکه و فروشگاه 🪙🛒
سکه از امتیاز **جدا** است — چون امتیاز هرگز کم نمی‌شود ولی سکه خرج می‌شود.

| سکه از کجا | چقدر |
|---|---|
| پایان هر بازی | ۶ تا ۱۶، بسته به درصد (+۱۵ اگر ۱۰۰٪) |
| هر سطح بالاتر | ۲۵ |
| هر نشان تازه | ۳۰ |
| هر مأموریت روزانه | نصف امتیازش |
| چالش روزانه | ۲۰ + ۵ × روزهای زنجیره |

فروشگاه شش قلم دارد: یک جان (۳۰)، پر کردن جان‌ها (۱۱۰)، یخِ زنجیره (۸۰)،
پوستهٔ کویر (۲۵۰)، چهرک‌های ویژه (۱۵۰) و هدیه به نورستان (۵۰۰).

دو قاعده که سخت رعایت شده‌اند: هر قلمی که فروخته می‌شود **واقعاً کاری می‌کند**،
و اگر اثرش نگرفت سکه **برمی‌گردد**. همچنین همیشه «درآمد − خرج = سکه»؛ اگر
این تساوی به هم بخورد `sanitize` خودش هم‌ترازش می‌کند.

### ج) زنجیره و هشدارش 🔥🧊
زنجیره از «تاریخ آخرین بازی» خوانده می‌شود نه از یک شمارنده، تا اگر برنامه
چند روز بسته بماند خودش بشکند. اگر زنجیره‌ای باشد و امروز بازی نشده باشد،
در خانه و در سرصفحهٔ بازی‌ها هشدار می‌آید — با دو دکمه: «بزن» (چالش روزانه)
و «🧊» (یخ زدن با ۸۰ سکه). یخ همان کارِ روزِ بازی‌شده را می‌کند ولی جایزه نمی‌دهد.

### د) مأموریت هفتگی 🏆
سه مأموریت تازه هر هفته، از **شنبه** تا شنبه. انتخابشان با بذرِ تاریخ است تا
روی همهٔ دستگاه‌ها یکی باشند. هفتهٔ UTC حساب می‌شود چون `U.today()` هم UTC
است؛ اگر یکی محلی و دیگری UTC بود، نزدیک نیمه‌شب کلید هفته یک روز جابه‌جا می‌شد.

### ه) تازه‌وارد و راهنمای شناور 🎬💡
چهار اسلاید کوتاه (خوش‌آمد، بازی‌ها، حافظ نور، نشان و سکه) **یک بار** و فقط
برای کاربری که هنوز امتیازی ندارد. بعد از پردهٔ آغازین می‌آید، نه پشتش — و
هر وقت خواستی از پروفایل دوباره بازش می‌کنی.

راهنمای شناور دو راه دارد: نگه‌داشتن انگشت روی هر عنصر `data-tip` (۶۲۰ms)، یا
روشن کردن «راهنمای لمسی» که با یک ضربه توضیح را نشان می‌دهد و مانع کار خودِ
دکمه می‌شود. متن راهنماها روی نوار پایین، نشان سکه و کارت چالش روزانه گذاشته شده.

### و) پوستهٔ ششم 🏜
پوستهٔ **کویر** اضافه شد (گرم و خاکی). در فروشگاه با ۲۵۰ سکه باز می‌شود و پیش
از خرید قفل است: نه در تنظیمات انتخاب می‌شود، نه چرخش سریع پوسته رویش می‌ایستد.

### ز) یک اشتباه که دوباره وقت‌گیر شد
در وصله‌های متنی، `String.replace` با **رشتهٔ** جانشین، `$$` را به یک `$`
تبدیل می‌کند. هفت جا `U.$$(` به `U.$(` بدل شد و سه سنجش شکست. حالا
`_patch.js` جانشین را **تابع** می‌دهد تا این دام برداشته شود.

## ۶.۱۰ منابع معارف — چه چیزی آورده شد و چه چیزی بیرون ماند

متن عربی هیچ حدیث، دعا یا حکمتی از حافظه نوشته نشده؛ همه از منبع زنده و بایت‌به‌بایت خوانده شده و هر ادعا با **دو منبع مستقل** سنجیده شده است. هر جا اختلاف بود، آن مورد **بیرون ماند** نه اینکه روایت دلخواه انتخاب شود:

| مورد | چرا بیرون ماند |
|---|---|
| تاریخ مباهله | منابع هم‌داستان نبودند |
| شهربانو به‌عنوان مادر امام سجاد (ع) | اختلاف روایت |
| نام مادر امام عسکری (ع) | اختلاف روایت |
| خاک‌سپاری سر امام حسین (ع) | اختلاف روایت |
| قاتل امام حسین (ع) | اختلاف روایت |
| بیشتر طول‌های امامت | اختلاف در شمار سال |
| ترجمهٔ دو فراز خطبهٔ طاووس و خفّاش | ترجمهٔ قابل‌استناد پیدا نشد |

فیلدهای مورد اختلاف در `DATA.imams` عمداً `null` مانده‌اند و `ImamEngine` فقط از فیلدهای غیرتهی پرسش می‌سازد — یعنی دادهٔ اختلافی نمی‌تواند به پرسش راه پیدا کند. `selfTest` هم می‌سنجد که زمینه‌های نامعلوم پرسش نساخته باشند.

## ۶.۱۱ تازه‌های نسخهٔ ۱۶ (ب) — نصب، آفلاین و آیکن‌های واقعی

پیش از این، نورستان «PWA» بود روی کاغذ: `manifest.json` و `sw.js` داشت، ولی
شرط نصب کروم هرگز برآورده نمی‌شد. سه چیز کم بود و هر سه درست شد.

### الف) آیکن‌ها دیگر ساختگی نیستند

مانیفست به شش فایل اشاره می‌کرد که **هیچ‌کدام وجود نداشتند**:
`icon-192.webp`، `icon-192.jpg`، `icon-512.webp`، `icon-512.jpg`،
`maskable-512.jpg` و دو تصویر `screenshots`. کروم برای پیشنهاد نصب، آیکن
≥۱۹۲ پیکسلِ **قابل دریافت** می‌خواهد؛ با آیکن ناموجود، `beforeinstallprompt`
هرگز صدا زده نمی‌شد و دکمهٔ نصب هرگز نمی‌آمد.

هیچ ابزار تصویری هم در دست نبود. پس `_icons.js` نوشته شد: کدگذار PNG با
`zlib` خودِ Node و `crc32` دست‌نویس. حرف «ن» با **ریاضیِ فاصلهٔ علامت‌دار**
(SDF) کشیده می‌شود — کمان برای کاسه، کپسول برای دُم، دایره برای نقطه — و بعد
با فرانمونه‌برداری ۳×۳ رستر می‌شود. خروجی: `icon-192.png`، `icon-512.png`،
`maskable-512.png` (نسخهٔ امن برای برش دایره‌ای اندروید)،
`apple-touch-icon.png` (۱۸۰) و `favicon-32.png`.

نکتهٔ هندسی که دو بار طول کشید: کاسهٔ «ن» نباید نیم‌دایرهٔ کامل باشد. با کمان
۰→۱۸۰ درجه، عمق و پهنای شکل برابر می‌شود و حرف به «U» لاتین می‌ماند. کمان
۲۰→۱۶۰ درجه نسبت عمق/پهنا را حدود ۰٫۳۵ می‌کند که نسبتِ درستِ «ن» است — و
بازوی چپ کوتاه‌تر از راست درمی‌آید.

`icon.svg` دست‌نویس هم ساخته شد، ولی چون دو آیکن داشتن یعنی دو جا برای
واگرا شدن، سنجش‌ها اعداد SVG را با همان `gmap()` می‌سنجند که PNG از آن
ساخته می‌شود. اگر یکی را عوض کنی و آن یکی جا بماند، تست می‌گیرد.

**چرا هر دو؟** Safari آیکن برداری را برای `apple-touch-icon` نمی‌پذیرد، پس
`icon.svg` تنها کافی نبود؛ و آیکن رستری دست‌کم در یک اندازه لازم است چون
مرورگر باید بتواند ابعادش را بخواند.

### ب) دکمهٔ نصب و راهنمای هر پلتفرم

`beforeinstallprompt` یک فرصت یک‌بارمصرف است. دو دام دارد:

۱. **زمان گرفتنش.** اگر شنونده را داخل `init()` بگذاریم، ممکن است رویداد
   پیش از آن رسیده باشد و از دست برود. پس همان‌جا در زمان پارس، بالای
   اسکریپت گرفته می‌شود.
۲. **`preventDefault()`.** بی آن، کروم نوار کوچک خودش را نشان می‌دهد و رویداد
   «سوخته» می‌شود — دیگر با `prompt()` بازشدنی نیست.

روی این پایه، `Install` یک ماشین حالت چهارحالته است:

| حالت | معنی | دکمه چه می‌کند |
|---|---|---|
| `installed` | همین حالا در حالت برنامه‌ایم | دکمه‌ای نیست؛ فقط تأیید وضعیت |
| `ready` | رویداد در دست است | نصب واقعی |
| `manual-ios` | iOS؛ دکمهٔ خودکار هرگز ندارد | راهنمای گام‌به‌گام |
| `manual` | بقیهٔ مرورگرها | راهنمای گام‌به‌گام |

اشتباه رایج این است که برای همه یک دکمه بگذاریم؛ آن‌وقت کاربر آیفون هر بار
می‌زند و هیچ نمی‌شود. اینجا دکمه **هیچ‌وقت بی‌واکنش نمی‌ماند**: اگر رویداد
آماده است نصب می‌کند، وگرنه راهنما را باز می‌کند.

راهنمای اندروید مسیر سه‌نقطهٔ کروم را می‌گوید، راهنمای iOS فقط Safari را
(کروم روی iOS چنین کاری نمی‌کند) و مسیر «Add to Home Screen» را، و راهنمای
رایانه آیکن نصب نوار آدرس را. کارت و دکمه در **تنظیمات ← نصب اپلیکیشن** است.

### ج) صفحهٔ آفلاین

`offline.html` ساخته شد: **کامل خودبسنده** — نه فونت CDN، نه تصویر بیرونی، نه
اسکریپت بیرونی. اگر همین صفحه به شبکه نیاز داشته باشد، دقیقاً همان لحظه‌ای که
شبکه نیست نمی‌آید. پس فونت سیستمی و شکل «ن» به‌صورت SVG درون‌خطی.

در `sw.js` به `PRECACHE` اضافه شد و **مسیر واپس‌رویِ رفت‌وبرگشت‌ها** شد، ولی
با ترتیب درست: اول `index.html` از کش (تجربهٔ کامل برنامه، چون کل برنامه
آفلاین کار می‌کند)، و صفحهٔ آفلاین فقط وقتی می‌آید که واقعاً چیزی برای نشان
دادن نباشد — نصب اول + بی‌شبکه.

نبودنِ خودِ `offline.html` عمداً نصب را می‌شکند: وعدهٔ «آفلاین باز می‌شود» بی
آن توخالی است.

### د) تگ‌های ایستا در `<head>`

`manifest`، `apple-touch-icon`، `apple-mobile-web-app-capable`،
`apple-mobile-web-app-title`، `mobile-web-app-capable` و
`apple-mobile-web-app-status-bar-style` حالا **ایستا در سند** هستند، نه
تزریق‌شده با JS. Safari هنگام «Add to Home Screen» این‌ها را در لحظهٔ پارس
می‌خواند و به تزریق بعد از بارگذاری اتکا نمی‌کند.

`Assets.pwa()` هم دیگر `link` آیکن نمی‌سازد — پیش‌تر به همان
`icon-192.webp` ناموجود اشاره می‌کرد و کروم همان را برمی‌داشت.

### ه) کش سرور

`serveFile` در `server.js` حالا `sw.js` و `manifest.json` را `no-cache`
می‌فرستد. با `max-age=3600` پیشین، به‌روزرسانی سرویس‌ورکر تا یک ساعت عقب
می‌افتاد و کاربر نسخهٔ کهنهٔ کش را نگه می‌داشت — همان چیزی که PWA نباید بکند.

### و) چه چیزی اینجا تست نشد

سه سنجشی که فقط روی دستگاه واقعی معنا دارند و من نمی‌توانم انجامشان بدهم:

- آمدن گزینهٔ نصب روی **Chrome اندروید**
- کار کردن «Add to Home Screen» روی **Safari iOS**
- باز شدن آفلاین پس از نصب

آنچه تست شد: اعتبار مانع‌های مانیفست و وجود و ابعاد واقعی هر آیکن (از خودِ
بایت‌های PNG خوانده می‌شود، نه از ادعای مانیفست)، خوانش `sw.js` با `vm.Script`،
خودبسندگی `offline.html`، ایستا بودن تگ‌های head، ماشین حالت نصب در هر چهار
حالت، رفتار `prompt()` در پذیرش/رد/خطا/آبجکت‌نشدن، خوانایی SVG با هندسهٔ PNG،
و سرو شدن واقعی همهٔ این فایل‌ها روی HTTP با نوع MIME درست.

## ۶.۱۲ تازه‌های نسخهٔ ۱۷ — چرا صوت در PWA پخش نمی‌شد

### الف) نشانه و ریشه

کاربر گفت: «صوت در PWA پخش نمی‌شود ولی بدون سرویس‌ورکر کار می‌کند.» این
دقیقاً سرنخِ درست بود: تفاوت میان دو حالت، تنها یک لایه است — سرویس‌ورکر.
پس باگ در `index.html` نبود، در `sw.js` بود.

زنجیرهٔ علت:

۱. عنصر `<audio>` بدون `crossOrigin` ساخته می‌شود (در کل برنامه هیچ‌جا
   `crossOrigin` ست نشده)، پس مرورگر درخواست را با حالت `no-cors` می‌فرستد.
۲. پاسخ چنین درخواستی **مبهم** (opaque) است: `type === 'opaque'`،
   `status === 0`، `ok === false` و بدنه‌اش خواندنی نیست.
۳. `sw.js` برای دامنهٔ قاریان `networkFirst()` را صدا می‌زد و آن تابع با
   معیار `res.ok` می‌سنجید. برای صوت `ok` همیشه `false` است، پس
   `throw new Error('bad status')` می‌خورد.
۴. شاخهٔ `catch` در کش هم چیزی نمی‌یافت (کش صوت همیشه خالی بود، چون همان
   `ok === false` مانع نوشتنش می‌شد) و در پایان یک **۵۰۳ با بدنهٔ JSON**
   برمی‌گرداند.
۵. مرورگر جای فایل صوتی، JSON با کد ۵۰۳ می‌گرفت و پخش شکست می‌خورد.

نکتهٔ مهم: کدْ خطای نگارشی و منطقیِ آشکاری نداشت. `if(res.ok)` روی کاغذ
درست است و در همهٔ مسیرهای هم‌خاستگاه هم واقعاً درست کار می‌کرد. تنها جایی
که می‌شکست، پاسخِ بین‌خاستگاهیِ `no-cors` بود — و همین یک جا، کل پخش صوت
برنامه را از کار انداخته بود.

### ب) چه تغییر کرد

**۱) صوت و ویدئو کامل به مرورگر واگذار می‌شود.** در `sw.js` تابع `isMedia()`
و یک شاخهٔ بازگشتِ زودهنگام اضافه شد که پیش از همهٔ شاخه‌های دیگر می‌آید و
هیچ `respondWith` ندارد:

```js
if(isMedia(req, url)) return;   // به مرورگر بگذار مستقیم هندل کند
```

«واگذاری کامل» یعنی هیچ لایه‌ای میان مرورگر و سرور نیست. سه چیز هم‌زمان
درست می‌ماند:

- **هدر `Range`** دست‌نخورده می‌رسد. پخش‌کننده‌ها برای ورق‌زدن در فایل با
  `Range` درخواست می‌فرستند و پاسخش ۲۰۶ است؛ `Cache API` در `put()` برای
  ۲۰۶ استثنا می‌دهد، پس هر طرحی که صوت را کش کند شکننده است.
- **`Content-Type`** همان است که سرور گفته (`audio/mpeg` برای mp3،
  `audio/ogg` برای ogg). سرویس‌ورکر نه عوضش می‌کند و نه از دستش می‌دهد.
- **هدرهای CORS** دست‌نخورده‌اند. `crossOrigin` نه ست می‌شود و نه لازم است.

**۲) تشخیص، چندلایه است.** هیچ‌کدام از این نشانه‌ها تنها کافی نیست:

| نشانه | چرا هست | چرا تنها کافی نیست |
|---|---|---|
| `req.destination` | مرورگر خودش می‌داند برای عنصر صوتی است | در تست‌های نودی خالی می‌ماند |
| پسوندِ نشانی | ساده و صریح | بعضی CDNها بی‌پسوند سرو می‌کنند |
| دامنهٔ قاریان | everyayah، islamic.network، quranicaudio، mp3quran | دامنهٔ تازه‌ای ممکن است اضافه شود |
| هدر `Range` | هر درخواست جزءبه‌جزء | فقط وقتی پخش از میان فایل باشد |

**۳) `networkFirst()` دیگر پاسخ مبهم را خطا نمی‌شمارد.** این محافظ حتی اگر
روزی صوت از مسیر `isMedia` بیرون بیفتد، همان باگ را می‌بندد:

```js
if(res && (res.type === 'opaque' || res.type === 'opaqueredirect')) return res;
```

**۴) تابع `storable()` جای `if(res.ok)` را گرفت.** فقط پاسخ `status === 200`
و غیرمبهم کش می‌شود. دو استثنا را رد می‌کند: ۲۰۶ (که `Cache API` در `put`
برای آن استثنا می‌دهد) و پاسخ مبهم (که بازیابی‌اش بی‌معناست). پاسخ‌های
۲۰۶ و ۲۰۴ همچنان *تحویل داده می‌شوند*، فقط کش نمی‌شوند.

**۵) شاخهٔ `everyayah.com|islamic.network` با `networkFirst` برداشته شد** —
با وجود شاخهٔ صفر دیگر هیچ‌وقت اجرا نمی‌شد و کد مرده بود.

**۶) نسخهٔ کش ۱۶ → ۱۷.** برای همهٔ کش‌ها، تا نسخهٔ قدیمی به کاربر تحمیل نشود.

### ج) یک جا با درخواست شما موافق نکردم

شما نوشتید «مطمئن شو فقط same-origin کش شود». این را عیناً اجرا نکردم و
دلیلش این است:

فونت‌های jsDelivr هم — دقیقاً مثل صوت — با `no-cors` می‌آیند و پاسخشان
مبهم است. ولی برخلاف صوت، پاسخ مبهمِ فونت برای `<link rel=stylesheet>`
**قابل استفاده است** (مرورگر بدنه را برای CSS می‌خواند؛ ما فقط نمی‌توانیم
از JS بخوانیمش). همین‌ها هستند که برنامه را آفلاین خوانا نگه می‌دارند.

اگر کشِ بین‌خاستگاهی را کامل ممنوع می‌کردم، شرط «آفلاین باز می‌شود» بی‌صدا
از دست می‌رفت — یعنی باگی از یک جا برداشته می‌شد و از جای دیگر سر می‌زد.

کاری که به‌جایش کردم، همان قصدِ شما را برمی‌آورد ولی بی آن هزینه:

- کشِ **درخت پوسته** (`SHELL`) فقط هم‌خاستگاهی است؛ دامنهٔ بیرونی هرگز در
  آن نوشته نمی‌شود.
- کشِ بین‌خاستگاهی جدا و کراندار است (`MEDIA` با سقف ۱۲۰ قلم، `TEXT` با
  سقف ۲۶۰) و با `trim()` قدیمی‌ها می‌ریزند.
- پاسخ مبهم هرگز کش نمی‌شود. یعنی از فونت‌ها فقط آنچه واقعاً به‌کار می‌آید
  می‌ماند، و هیچ چیزِ بی‌مصرفی در کش نمی‌نشیند.

### د) و یک چیز که هنوز نیست

الان **هیچ صدایی آفلاین پخش نمی‌شود** — نه پیش از این تغییر و نه بعدش.
پیش از تغییر، کش صوت همیشه خالی بود (چون `ok === false` مانع نوشتنش
می‌شد)؛ بعد از تغییر هم عمداً خالی می‌ماند.

کش کردنِ پاسخ مبهم در `Cache API` راه‌حل نیست، چون بدنهٔ مبهم برای
`<audio>` بازیابی‌شدنی نیست. راه درست، کارِ **فاز ۵ (حافظ نور)** است:
صدای آیه‌های حفظ‌شده را با `fetch` و `mode: 'cors'` بگیریم و به‌صورت
`ArrayBuffer` در **IndexedDB** بنشانیم — همان‌جا که در پرامپت اصلی هم
خواسته شده بود. آن مسیر، برخلاف این یکی، واقعاً آفلاین کار می‌کند.

### ه) تست‌ها

۲۱ سنجش تازه در سه بخش: «صوت در PWA — رهگیری نمی‌شود»، «پاسخ مبهم هرگز
۵۰۳ نمی‌شود» و «هیچ مسیر صوتی به کش نمی‌رسد».

نکتهٔ روش: این باگ **رفتاری** بود، نه متنی. هیچ عبارت باقاعده‌ای نمی‌گرفت
که «پاسخ مبهم، ۵۰۳ می‌شود» — کدْ خوانا و خوش‌ساخت بود و همان کد صوت را
می‌کشت. پس تست‌ها فقط متن `sw.js` را نمی‌خوانند، بلکه خودِ سرویس‌ورکر را
در `vm` با یک `self` جعلی بار می‌کنند و `fetch handler` واقعی را با
درخواست واقعی صدا می‌زنند. شبیه‌ساز `Cache API` هم عمداً مثل خودِ مرورگر
برای ۲۰۶ استثنا می‌دهد، وگرنه تستْ باگی را که مرورگر واقعاً دارد تأیید
نمی‌کرد.

و برای آنکه تست بی‌اثر نباشد، منطقِ نسخهٔ ۱۶ عیناً در تست بازسازی شده و
روی همان پاسخ مبهم اجرا می‌شود؛ باید ۵۰۳ بدهد. اگر روزی کسی آن محافظ را
بردارد، این سنجش قرمز می‌شود و می‌گوید چرا گذاشته شده بود.

آنچه این‌جا هم تست نشد: **پخش واقعی صوت در PWA نصب‌شده**. من نمی‌توانم
مرورگری اجرا کنم. آنچه می‌توانستم و کردم: اثبات اینکه درخواست صوت دیگر
رهگیری نمی‌شود و هیچ مسیری آن را به ۵۰۳ تبدیل نمی‌کند.

## ۷. کارهایی که در نسخهٔ ۱۲ خراب بود و درست شد

1. **ورود مدیر هرگز کار نمی‌کرد** — هش ذخیره‌شده در نسخهٔ ۱۲ (`8d969eef…`) هش واقعی `noor2024` نبود. هش درست جایگزین شد و کاربران قدیمی هم مهاجرت داده می‌شوند.
2. **«ورود به روم» ساختگی بود** — بعد از ۵۰۰ms یک روم قلابی با نام «روم مهمان» باز می‌شد. حالا روم واقعی ساخته/وصل می‌شود.
3. **هش SHA-256 روی HTTP کار نمی‌کرد** — پیاده‌سازی خالص JS جایگزین شد.
4. **ضربان شبکه با تغییر صفحه می‌مرد** — تایمرها به دو استخر «صفحه» و «سیستم» تقسیم شدند.
5. **حروف اسم فامیل برنمی‌گشت** — مدل «استخر اشیاء» جای `indexOf('_')` را گرفت.
6. **نشت شنوندهٔ دوز** — هر بار ورود به بازی یک شنونده اضافه می‌شد.
7. **دور بعد اسم فامیل در حالت محلی جلو نمی‌رفت** — پیام `phase:'next'` حالا در هر دو مسیر مسیریابی می‌شود.
8. **ساخت روم دوم بی‌پیام رد می‌شد** — کلاینت اول خروج می‌فرستد، بعد روم تازه می‌سازد.
