# نورستان — لایهٔ محتوا و سیستمِ طراحیِ Material 3

**تاریخ:** ۲۰۲۶-۱۰-۱۳ · **شاخه:** `arena/435b5423-noorestan` · **نسخهٔ کشِ سرویس‌ورکر:** ۴۹ (۴۸ در ۲۰۲۶-۱۰-۱۳ با فایل‌های تازهٔ M3/محتوا؛ ۴۹ در ۲۰۲۶-۱۰-۱۴ با سخت‌سازیِ لایهٔ محتوا)

این سند دو لایهٔ تازهٔ برنامه را توضیح می‌دهد:

1. **لایهٔ محتوا** (`NoorContent` در `assets/app/content-1.js`) — تنها منبعِ متن و عددِ عبادت‌ها.
2. **لایهٔ طراحی و رفتارِ Material 3** (`assets/styles/m3.css` + `assets/app/m3-1.js`) — توکن‌ها، نقش‌های رنگ،
   چیدمانِ سازگار، حالت‌های تهی/خطا/بارگذاری، دسترس‌پذیری و مقیاسِ قلم.

> ⚠️ **محدودیتِ راستی‌آزمایی:** در این محیط هیچ مرورگری نصب نیست (chromium/firefox/puppeteer/playwright هیچ‌کدام).
> همهٔ سنجش‌ها با هارنسِ Node (`_harness.js` با DOMِ استاب)، بررسیِ منبع، و `tools/ci.sh` انجام شده است.
> **هیچ تأییدِ بصریِ واقعی صورت نگرفته** — پیش از انتشار باید `_ayah-vertical-tests.js` و
> `NOOR_BROWSER_GATE=1 bash tools/ci.sh` روی دستگاهِ دارای مرورگر اجرا شود.

## ۲) مدلِ دادهٔ محتوا

> **به‌روزرسانیِ نسخهٔ ۲۳ب (۲۰۲۶-۱۰-۱۴):** این لایه سخت‌تر شد — `validate()`/`diff()`/`log`،
> چهار شرطِ `pending()`، `gaps()`/`isPending()`/`pendingSummary()` آگاه به نوعِ رکورد، و
> **پلِ دعاها** (`adoptDuas`) که ۱۴ دعوای بانکِ قفل را به رکوردهای `type:'dua'` نگاشت می‌کند
> (۳۸ رکورد در کل). قراردادِ کامل و گزارشِ وضعیت: `docs/CONTENT-LAYER-2026-10-14.md`.

هر رکورد یک **واحدِ عبادیِ مستقل** است:

| فیلد | نوع | قاعده |
|---|---|---|
| `id` | string | یکتا؛ مجموعه‌ها `zahra`، فازها `zahra.takbir`، مرحله‌های نماز `step.sujud` |
| `type` | `dhikr-set` \| `dhikr` \| `prayer-step` | نوعِ واحد |
| `title` / `shortTitle` | string | نامِ فارسی برای فهرست و تب |
| `arabicText` | string \| `null` | `null` یعنی **در منبع نیامده** — هرگز حدس زده نمی‌شود |
| `translationFa` | string \| `null` | همان قاعده |
| `repeatCount` | number \| `null` | `null` ⇒ UI جایِ خالی می‌دهد و شمارنده باز می‌ماند |
| `category` | string | `تعقیباتِ نماز` / `نماز` / `شخصی` |
| `order` | number | ترتیبِ نمایش — فقط از داده، نه از ترتیبِ کد |
| `phases` | string[] | فقط در `dhikr-set`: شناسهٔ فازها **به ترتیب** |
| `parent` | string | فقط در `dhikr`: مجموعهٔ والد |
| `notes` | string | یادداشتِ کوتاه (مثلاً «پس از هر نماز») |
| `source` | string | **اجباری** — از کجا آمده |
| `verified` | boolean | کلِ رکورد تأیید شده؟ فقط با ورودیِ صریحِ صاحبِ برنامه `true` |
| `verifiedText` | boolean | فقط *متن* تأیید شده (عدد نه) |
| `tags` | string[] | برای جست‌وجو |

### تابع‌های عمومی

| تابع | کار |
|---|---|
| `item(id)` / `all()` / `byType(t)` / `byCategory(c)` / `categories()` | دسترسی به رکوردها |
| `phases(setId)` | فازها **مرتب‌شده بر `order`** با `{id, ar, fa, n, title, verified}` |
| `goalTotal(setId)` | جمعِ هدف‌های شناخته‌شده؛ `null` اگر هیچ هدفِ ثبت‌شده‌ای نباشد |
| `countSummary(setId)` | «۳۴/۳۳/۳۳» — ساخته‌شده از داده؛ فازِ بی‌هدف `—` می‌شود |
| `repeatLabel(itemOrId)` | `{known, text, value, verified}` — اگر `null` باشد: «تعدادِ تکرار در منبع ثبت نشده است» |
| `preset(setId)` / `presetIds()` | پیش‌تنظیمِ ذکرشمار (`editable:false` برای دادهٔ تأییدشده) |
| `prayerStep(id)` | `{ar, fa, n, verified, source}` برای `Sajjada.TXT` |
| `register(incoming, meta)` | ورودیِ تازه: ادغام با رکوردِ موجود یا افزودن؛ **متنِ تأییدشدهٔ تازه بر قدیمی می‌چربد** |
| `pending()` | فهرستِ همهٔ جایِ خالی و تأییدنشده‌ها — همان چیزی که در UI «در انتظارِ منبعِ معتبر» است |
| `selfTest()` | ۱۰ سنجشِ ساختاری (بی DOM) |

### وضعیتِ تأییدِ داده (۲۰۲۶-۱۰-۱۳)

* **تأییدشده (`verified:true`) — ۴ رکورد:** `zahra` و سه فازش (`zahra.takbir` ۳۴، `zahra.hamd` ۳۳،
  `zahra.tasbih` ۳۳). منبع: «ورودیِ تأییدشدهٔ صاحبِ برنامه — ۲۰۲۶-۱۰-۱۳».
* **متنِ تأییدشده، عددِ تأییدنشده:** `step.sujud` — متن «سُبْحانَ رَبِّیَ الأَعْلیٰ وَ بِحَمْدِهِ»
  (`verifiedText:true`)، تعدادِ تکرار از نسخهٔ پیشین (`verified:false`) و در `pending()`.
* **۲۰ رکورد در `pending()`** — همهٔ مرحله‌های دیگرِ نماز و مجموعه‌های
  `istighfar / tahlil / hawqala / salawat / custom`. عددهایشان برای کارکردِ برنامه نگه داشته شده
  ولی **تأییدشده علامت نخورده‌اند** و در UI با نشانِ «در انتظارِ منبعِ معتبر» دیده می‌شوند.
* `step.dhikr34.repeatCount = null` و `custom.1` کاملاً خالی ⇒ UI جایِ خالی نشان می‌دهد.

## ۴) Material 3 — توکن‌ها و نقش‌ها

`assets/styles/m3.css` (۵۳٫۷ KB) **آخرین** برگِ استایل است (پس از `style-1`، `sanctuary`، `polish`)
تا نقش‌های M3 بر پوستهٔ پیشین بنشینند.

* **نقش‌ها از توکن‌های موجود ساخته می‌شوند** (`--md-primary` از `--gold`، `--md-surface` از `--bg`،
  `--md-surface-container` از `--card` و …) ⇒ هر شش پوستهٔ برنامه
  (`dark / ocean / forest / royal / desert / light`) بدونِ تغییر کار می‌کنند.
* **لایهٔ وضعیت:** `--md-hover:.08`، `--md-focus:.10`، `--md-press:.10`، `--md-drag:.16` با
  `color-mix()` و واپس‌رویِ `@supports not (color: color-mix(...))`.
* **ارتفاع و هدفِ لمس:** `--md-target:48px`، `--md-nav-h:80px`، `--md-rail-w:96px`، `--md-max-w:1200px`.
* **شکل و سایه:** `--md-shape-*` و `--md-elev-*` (۱..۵) با لایهٔ سطح (`surface-container`).
* **تایپوگرافی:** `--md-display-*` … `--md-label-*` (۱۸ توکن) و سه توکنِ
  **`--md-sacred-large/medium/small`** برای متنِ عربی با `var(--f-quran)` (= Amiri).
  مقیاسِ کلی با `--md-ts` (از `M3.setTypeScale('sm'|'md'|'lg')`) بزرگ/کوچک می‌شود،
  بی آن‌که اندازهٔ `.read-ar` (متنِ قرآن) دست بخورد.
* **حرکت:** از `--dur-*`/`--ease-*` خودِ برنامه (`motion.css`) استفاده می‌شود و
  `prefers-reduced-motion` همهٔ انتقال‌ها را کوتاه می‌کند.

### قلم‌ها

| قلم | نقش | منبع |
|---|---|---|
| Vazirmatn 400/700/800 | متنِ فارسیِ رابط | **محلی** (`assets/fonts/*.woff2`) |
| Amiri 400/700 | متنِ عربیِ ذکر/دعا/قرآن (`--f-quran`) | **محلی** (تازه) + پروانهٔ `Amiri-OFL.txt` |
| Lalezar | تیترهای تزئینی | محلی |

## ۵) چیدمانِ سازگار و RTL

* **سه شکستِ مرجعِ M3:** `600 / 840 / 1200` پیکسل. `M3.sizeOf()` همان‌ها را به
  `<html data-wsc="compact|medium|expanded">` می‌نویسد تا JS و CSS یک واقعیت را ببینند.
* **موبایل (`<840px`):** نوارِ پایینِ لبه‌به‌لبه با قرصِ ۶۴×۳۲ زیرِ آیکنِ فعال.
* **دسکتاپ/تبلتِ بزرگ (`≥840px`):** **ریلِ ۹۶ پیکسلیِ کنار** با `#nav::before` به عنوانِ فضا‌نگهدار و
  `#app{padding-inline-start:calc(var(--md-rail-w) + var(--md-gutter))}`.
* **حاشیه‌ها:** `--md-gutter: 16 / 24 / 32` پیکسل به ترتیبِ سه شکست.
* **RTL:** همه‌جا خاصیتِ **منطقی** (`padding-inline`, `margin-inline`, `inset-inline-*`,
  `border-start-start-radius`)؛ نشانِ اعلانِ `.iconbtn .dot` که پیش‌تر `left:5px` بود حالا
  `inset-inline-end` است. هر `left/right` باقی‌مانده عمداً `auto` و برای خنثی‌کردنِ قاعدهٔ قدیمی است.
* **جزئیاتِ هویتِ بصری برنامه حفظ شده:** طاقِ `.cat-ico` و `.tile .ti`، و شمارهٔ `.read-num` در
  `inline-end` متنِ قرآن.

## ۶) حالت‌های صفحه و دسترس‌پذیری

هر صفحه چهار حالت دارد و هیچ‌کدام خالی نمی‌ماند:

| حالت | ابزار | نمونه |
|---|---|---|
| دادهٔ عادی | رندرِ معمول | — |
| تهی | `M3.empty({icon,title,body,action})` → `.empty-state.m3-empty[data-m3-state="empty"]` | «موردی برای نمایش نیست» |
| بارگذاری | `M3.loading({rows})` / `M3.skeleton()` / `M3.spinner()` → `.m3-skeleton` | اسکلت به تعدادِ ردیف |
| خطا | `M3.error({icon,title,body,action})` → `.m3-error[data-m3-state="error"]` با «تلاشِ دوباره» | پیامِ محترمانه + کنشِ جایگزین |

* **اعلامِ صفحه:** `Router._render` پس از نشاندنِ صفحه رویدادِ `noor:screen` را
  `dispatchEvent` می‌کند و `M3` آن را در منطقهٔ زندهٔ `#m3Live` (`role="status"`,
  `aria-live="polite"`, `aria-atomic="true"`, کلاسِ `.m3-live.sr`) اعلام می‌کند —
  صفحه‌خوان با هر جابه‌جایی نامِ صفحه را می‌شنود.
* **نوارِ پیشرفت:** `M3.progressbar(el, value, max, text)` نقش و
  `aria-valuemin/max/now/text` را همگام می‌کند. **دو دامِ شناخته‌شده قفل شده‌اند:**
  مقدارِ نامعلوم «۰٪» نمی‌شود (`aria-valuenow` برداشته می‌شود) و متنِ تهی
  `aria-valuetext`ِ دست‌نویس را **برمی‌دارد**. `M3.syncProgress()` درصدِ هر
  `[role="progressbar"]` را از پهنای خودِ پرکننده می‌خواند تا منبعِ حقیقتِ دوم ساخته نشود.
* **حلقهٔ تمرکز:** `polish.css` با `:where(...):focus-visible{outline:none!important}` همهٔ
  حلقه‌ها را می‌کشت؛ `m3.css` همان `:where()` را با `!important` دوباره تعریف می‌کند و
  `--ds-focus`/`--pl-ring` را بازمی‌گرداند ⇒ حلقهٔ ۲ پیکسلیِ `--md-primary`.
* **بازخوردِ لمسی:** ریپلِ M3 (`M3.ripple`) روی دکمه‌ها و کاشی‌ها، با خاموش‌شدن در
  `prefers-reduced-motion`.

### i18n

* زبانِ رابط امروز **فقط فارسیِ تأییدشده** است: `M3.STRINGS` تنها `fa` دارد و
  `setLang('en')` **رد می‌شود** (`lang` همان `fa` می‌ماند) — هیچ زبانِ دومی حدس زده نمی‌شود.
* زیرساخت آماده است: کلیدها ثابت‌اند (`loading/emptyT/emptyP/errorT/errorP/retry/screen/progress`)؛
  افزودنِ زبان = افزودنِ یک شیء به `STRINGS` (و در لایهٔ محتوا، افزودنِ `translationEn` به رکوردها).

## ۹) چگونه گسترش دهیم

**افزودنِ یک ذکرِ تازه (با منبعِ معتبر):**
```js
NoorContent.register([
  { id:'zikr.shab', type:'dhikr', title:'ذکرِ شب', arabicText:'…', translationFa:'…',
    repeatCount:null, category:'تعقیباتِ نماز', order:7, verified:true },
], { source:'ورودیِ تأییدشدهٔ صاحبِ برنامه — <تاریخ>' });
```
تا عدد تأیید نشده، `repeatCount:null` بگذارید — UI خودش جایِ خالی می‌دهد.

**افزودنِ زبان:** یک شیءِ کامل به `M3.STRINGS` + `translationEn` در رکوردهای محتوا.
**افزودنِ پوستهٔ رنگی:** توکن‌های پایه (`--bg/--card/--fg/--gold/…`) را در یک
`html[data-theme="…"]` تعریف کنید؛ نقش‌های M3 خودشان ساخته می‌شوند.

## ۱۰) کارهای باقی‌مانده

1. **راستی‌آزماییِ بصری روی مرورگرِ واقعی** (اجباری پیش از انتشار) — `NOOR_BROWSER_GATE=1 bash tools/ci.sh`
   و `node _ayah-vertical-tests.js` روی دستگاهِ دارای کرومیوم.
2. **تکمیلِ رکوردهای `pending()`** با منبعِ معتبر — از نسخهٔ ۲۳ب **۳۴ رکورد**
   (۲۰ ذکر/تسبیح/مرحلهٔ نماز + ۱۴ دعای منتقل‌شده از بانکِ قفل).
   جزئیات، جدولِ وضعیت و دستورهای ورودِ داده در `docs/CONTENT-LAYER-2026-10-14.md`.
3. **یک‌سان‌سازیِ نسخه‌ها:** `package.json` ۱۷، کلیدِ ذخیره `v14`، `_v` داده ۱۵، کشِ SW ۴۸ —
   چهار شمارهٔ متفاوت. تغییرِ کلیدِ ذخیره دادهٔ کاربر را پاک می‌کند، پس باید آگاهانه و با مهاجرت انجام شود.

   تغییرِ یک‌طرفه ورودی/خروجی را می‌شکند).
5. `duel.html`/`duel.js` مرده‌اند و در فهرستِ سفیدِ سرور نیستند — یا برداشته شوند یا برگردند.
